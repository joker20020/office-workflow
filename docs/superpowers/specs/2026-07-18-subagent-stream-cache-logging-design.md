# 子智能体流式显示、图像缓存与并发日志设计

## 目标

解决三个相互关联的运行时问题：

1. 子智能体的内部流式事件被显示为 `agentscope-subagent-event` 原始 JSON，且高频逐字符更新会使聊天界面卡顿。
2. 下载到 `data/tmp` 的图像不能稳定地在聊天记录中显示。
3. 多个进程同时写入按日期轮转的日志文件时，Windows 报告文件正在被占用。

本设计同时适用于 `main` 和 `solidworks` 分支的共享代码；SolidWorks 专有 MCP 代码不在本次变更范围内。

## 子智能体显示

### 事件协议与解析

插件继续通过不可见分隔前缀传递子智能体进度事件，但将连续的文本增量在产生端合并。UI 端新增增量解码缓冲区，因此可正确处理：

- 一个事件被拆成多个模型流分片；
- 一个流分片包含普通工具输出和一个或多个事件；
- 同一分片包含多个连续事件。

已识别的内部事件不会进入工具结果正文；非内部输出维持原样显示。

### 呈现与性能

工具结果块显示语义化的子智能体活动记录：开始、进行阶段、工具调用、工具结果、文本输出、警告/错误和完成。连续的同一子智能体文本合并为一个输出段，而不是逐 token 新增一行。

聊天面板将流式块更新放入短周期批次（约 50--100 ms）后再更新 Qt 控件。完成、错误和最终结果会立即刷新。原始事件仍以完整结构写入调试日志，便于排障，但不会直接暴露给最终用户。

高频普通文本块不会再以 `INFO` 级别逐条记录诸如 `Block update: text` 的无上下文日志。仅在块类型切换、工具/子智能体生命周期状态改变、合并批次统计或异常时记录可诊断信息；需要逐事件排查时使用 `DEBUG` 级别，并由节流后的批次摘要替代单 token 日志。

## `data/tmp` 图像缓存

图像下载统一受本地缓存路径策略约束，只允许写入项目根目录的 `data/tmp`。缓存文件名将规范化，必要时创建父目录；下载写入临时文件并在成功后原子替换目标文件，避免 UI 读取半写入文件。

下载响应将验证为可读取的图像数据，并保留与响应内容匹配的扩展名。聊天组件统一将绝对路径、相对项目路径和 `file://` URI 规范化为本地文件后再加载。加载失败时显示可诊断的占位说明，而不是静默空白。

## 并发日志

保留现有的单个日文件和轮转策略。新增跨进程文件锁处理器：

- 每次 `emit`（包括是否轮转、备份重命名和实际写入）获取同一个旁路锁文件的独占锁；
- 未获取锁时阻塞重试，持锁进程写入/轮转完成后释放；
- 锁由操作系统持有，异常退出后自动释放，避免遗留锁文件导致永久阻塞；
- `get_logger()` 使用进程内重入锁，避免并发初始化导致重复处理器。

Windows 使用 `msvcrt` 区域锁；非 Windows 平台使用 `fcntl.flock`，以便测试与未来部署保持可移植。不会新增第三方依赖。

## 验证

新增或扩展测试覆盖：

- 分片、混合和多事件流中不泄漏内部标记，且连续文本会合并；
- 高频子智能体输出被批处理，完成事件仍立即出现；
- `data/tmp` 图像原子缓存后能由本地路径和 `file://` URI 加载；
- 并发进程向同一轮转日志写入时无重复 handler、无访问冲突且记录完整。

完成后运行相关测试与两分支完整测试套件；共享提交先落在 `main`，随后拣选到 `solidworks`。
