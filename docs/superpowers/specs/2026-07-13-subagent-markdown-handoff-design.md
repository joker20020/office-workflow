# 子智能体结构化 Markdown 交接设计

## 目标

仅优化 `agent_extensions` 中 Unity、Blender、工艺规划和图片生成四个子智能体的系统提示词，使其最终答复稳定包含主智能体继续工作所需的信息。保持 AgentScope 调用方式、工具实现和现有返回结果组装逻辑不变。

## 约束

- 不引入 Pydantic `structured_model`。
- 不解析或重组 AgentScope memory。
- 不修改 `_make_response` 和四个公开工具的返回类型。
- 不通过插件代码读取或验证子智能体报告的文件。
- 子智能体最终答复使用 Markdown，不使用 JSON 外层封装。

## 统一交接模板

四个子智能体的系统提示词都必须要求最终答复严格包含以下章节：

```markdown
# 执行结果

## 状态
成功 | 部分成功 | 失败

## 完成摘要
说明实际完成的工作，不得把计划或尝试描述为已完成。

## 生成文件
- 类型：...
  路径：...
  用途：...
  验证：已验证 | 未验证

## 具体结果
记录本任务最重要、可继续使用的领域信息。

## 执行记录
- 使用的关键工具及结果

## 警告与未完成项
- 无；或列出失败、缺失、未经验证的内容及原因
```

没有生成文件时，`生成文件` 章节必须明确写“无”，不得省略。所有路径应尽可能使用绝对路径；工具没有返回路径时必须明确写“路径未提供”，不得猜测。

## 各子智能体的领域信息

### 工艺规划

- `生成文件` 列出全部工序与工步 JSON 文件路径。
- `具体结果` 按文件分别给出完整 JSON 内容，使用带语言标识的代码块。
- 写入文件后使用查看工具复核，说明 JSON 是否完整、工序与工步关系是否一致。
- 列出实际采用的检索知识和仍存在的不确定信息。

### 图片生成

- 对每张图片分别列出输出文件名或路径、实际使用的提示词、生成结果。
- 只有工具明确返回成功时才能标记成功。
- 当前工具未提供完整路径时明确写“路径未提供”，不虚构目录。

### Blender

- 列出创建、修改和删除的对象，关键尺寸、材质及检查视角。
- 列出 `.blend`、导出模型或渲染图路径；未执行保存或导出时明确说明。
- 只有实际调用工具并获得成功结果后才能声称完成。

### Unity

- 列出创建或修改的场景、GameObject、组件、脚本、资源和 AR 流程。
- 列出 Unity 工程、场景、脚本、构建产物等路径；工具未返回路径时明确说明。
- 列出调用的 MCP/custom tool 及关键结果，并区分已执行与建议执行。

## 错误处理

即使任务失败，子智能体也必须输出完整章节。失败原因放入“警告与未完成项”，已生成的中间文件仍需列入“生成文件”。不得用笼统的“任务完成”代替实际结果。

## 测试策略

通过读取插件源码中的四段提示词，验证统一章节、路径真实性约束以及每类智能体的领域专用要求均存在。测试不启动外部 MCP、ComfyUI 或语言模型。
