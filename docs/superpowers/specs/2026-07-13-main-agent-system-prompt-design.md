# 主智能体系统提示词优化设计

## 背景

`config/settings.yaml` 中的 `system_prompt` 当前只规定了“工艺优先、Unity 最后”和子工具之间需要传递工艺信息，但没有明确每个阶段的成功判定、输入输出、失败处理及最终交付格式。主智能体因此可能在依赖信息不足时提前调用下游工具，或丢失子智能体返回的文件路径和具体内容。

## 目标

将主智能体定义为固定流水线的规划与编排者，使其按顺序完成工艺生成、图片生成、Blender 建模和 Unity AR，并在阶段之间完整传递子智能体返回的结构化 Markdown 信息。

## 范围

- 只修改 `config/settings.yaml` 中的 `system_prompt`。
- 不修改模型、主题、最近工作流或其他配置。
- 不修改任何工具签名、子智能体提示词或返回结果组装代码。
- 不增加新的运行时代码或依赖。

## 主智能体职责

主智能体负责：

1. 理解用户目标并整理四阶段执行计划。
2. 按固定顺序调用工具。
3. 阅读每个子智能体返回的结构化 Markdown。
4. 判断阶段状态，校验下游依赖信息是否齐全。
5. 将上游结果完整传给下游工具。
6. 在失败时立即停止并给出可恢复的交付说明。
7. 全部成功后汇总所有阶段和生成文件。

主智能体不得自行虚构工艺内容、工具执行结果或文件路径，也不得将计划、建议、已发起调用等同于已成功完成。

## 固定执行流程

每个用户任务都必须按以下顺序执行：

1. 调用 `tool_generate_process` 生成工艺。
2. 调用 `tool_generate_image` 生成所需图片资源。
3. 调用 `tool_blender_model` 完成 Blender 建模。
4. 调用 `tool_unity_ar` 完成 Unity AR 辅助装配程序。

不得跳过或调换阶段。只有当前阶段明确返回“成功”且下游所需信息齐全时，才能进入下一阶段。

## 阶段结果读取与成功判定

每次调用子智能体工具后，主智能体必须读取其结构化 Markdown 中的以下章节：

- 状态
- 完成摘要
- 生成文件
- 具体结果
- 执行记录
- 警告与未完成项

只有“状态”为“成功”，且必要文件路径、具体内容和验证信息存在时，阶段才算成功。“部分成功”“失败”、缺少必需信息或结果相互矛盾时都视为阶段未完成，必须立即停止整个流水线。

## 上下文传递

### 工艺到下游阶段

向图片、Blender 和 Unity 工具传递：

- 完整工艺与工步内容；
- 工序和工步 JSON 文件路径；
- 关键工艺约束；
- 工具报告的警告和不确定项。

调用 Unity 工具时，`info` 参数必须是从工艺结果整理得到的工序工步 JSON，不能使用摘要代替。

### 图片到后续阶段

向 Blender 和 Unity 工具传递：

- 每张图片的文件路径或明确的“路径未提供”状态；
- 图片用途；
- 实际使用的生成提示词；
- 生成与验证状态。

### Blender 到 Unity

向 Unity 工具传递：

- `.blend` 工程路径；
- 导出模型、材质、贴图和渲染图路径；
- 对象名称、层级、尺寸和关键建模结果；
- Blender 阶段的验证状态和警告。

不得猜测或补造子工具没有返回的路径。缺少 Unity 必需的模型或资源路径时，Blender 阶段视为未完成并停止。

## 失败处理

任一阶段出现以下情况时立即停止，不调用后续工具：

- 状态为“部分成功”或“失败”；
- 工具抛出错误或没有返回结果；
- 缺少下游必需的文件路径或具体内容；
- 返回内容存在无法消解的矛盾；
- 文件或操作被标记为未验证。

失败答复必须列出：

1. 已成功完成的阶段；
2. 已生成文件的全部已知路径；
3. 停止所在阶段；
4. 子智能体返回的原始失败原因或警告；
5. 恢复执行前需要满足的条件。

不得在失败后自行假设结果并继续流水线，也不得自动重复已经明确成功的阶段。只有为了补齐当前阶段必需信息时，才允许重试当前阶段。

## 成功交付

四个阶段全部成功后，主智能体使用清晰的 Markdown 向用户汇总：

- 总体完成状态；
- 工艺、图片、Blender、Unity 四阶段的完成摘要；
- 按阶段分类的全部生成文件路径；
- 关键工艺、图片、模型和 Unity 配置信息；
- 仍需用户关注的警告；没有警告时明确写“无”。

最终答复必须基于工具实际返回内容，不得遗漏已生成文件，也不得声称未经验证的内容已经完成。

## 测试策略

新增针对 `config/settings.yaml` 的静态配置测试，验证：

- YAML 可以正常加载；
- 系统提示词包含四个工具名及固定顺序；
- 包含阶段成功门控和失败立即停止规则；
- 包含完整上下文与文件路径传递要求；
- 包含 Unity `info` 参数要求；
- 包含禁止猜测路径、禁止跳过阶段和最终汇总要求。

测试不启动语言模型、MCP、ComfyUI 或后端服务。
