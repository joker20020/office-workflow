# AR 装配交付

仅处理端到端的 AR 辅助装配交付。开始前确认目标确实涵盖工艺、图像、三维模型和 Unity AR；若用户只请求其中一部分，不使用本 Skill，而是按该部分的实际需求处理。

## 执行顺序

按依赖关系执行以下阶段：

1. 使用 `tool_generate_process` 生成完整工艺与工序工步文件。
2. 使用 `tool_generate_image` 根据已验证工艺生成图像资源。
3. 使用 `tool_blender_model` 根据已验证工艺和图像结果完成 Blender 建模。
4. 使用 `tool_unity_ar` 整合已验证的工艺、图片和 Blender 资产，完成 Unity AR 辅助装配程序。

不要跳过、调换或虚构阶段。只有当前阶段的实际结果完整且可供下游使用时，才开始后续阶段。

## 阶段校验与交接

- 每次工具调用后，读取结构化 Markdown 中的状态、完成摘要、生成文件、具体结果、执行记录、警告与未完成项。
- 只有状态为“成功”，且文件路径、内容与验证信息一致时，才视为成功。不得虚构工具结果、文件路径或验证状态。
- 发现“部分成功”、失败、未验证关键项、缺少下游必需文件或信息矛盾时，停止后续阶段；说明已完成阶段、已知路径、原始原因和恢复条件。
- 向下游完整交接真实信息，而非仅传递摘要：
  - 工艺阶段交接完整工艺与工步内容、JSON 路径、约束、警告与不确定项。
  - 图像阶段交接每张图的路径、用途、实际提示词与验证状态。
  - Blender 阶段交接 `.blend` 路径、导出模型、材质、贴图、渲染图、对象层级、尺寸与验证状态。
  - 调用 Unity AR 时，`info` 包含完整工序工步 JSON；`task` 说明工艺要求、图像资源、Blender 资产路径和预期 AR 行为。

## 重试与交付

- 只为补齐当前阶段必需信息而重试当前阶段；不要自动重复已经明确成功的阶段。
- 所有阶段成功后，用 Markdown 汇总总体状态、各阶段完成摘要、按阶段分类的全部实际文件路径、关键工艺信息、图像资源、Blender 模型、Unity 配置和警告。无警告时明确写“无”。
- 最终结论只基于工具实际返回；明确区分已完成、部分完成和未完成事项。
